# Configuration contracts

`ufu-do53.within.example.json` and `ufu-doh.within.example.json` are **gated examples**, not approved runnable genuine-data configurations. Their feature lists come from official documentation, not inspected archived headers. They expect separately added `row_id`/`capture_id` provenance columns and leakage-controlled processed inputs. Actual source files, categorical RR type/class treatment, aggregates and normalization must be audited first. Set the provenance acknowledgement flags only after documenting that audit; the software records the acknowledgement and cannot certify authenticity.

`transfer.blocked.example.json` deliberately has an empty compatibility list. The published principal CSV schemas have no predictor-name intersection; a common extractor and observation contract are required. It fails rather than inventing a matrix. Each compatible entry must contain exactly `name`, `source_column`, `target_column`, `definition`, `unit`, `window`. Ordered dataset feature lists must match the mapping.

Source and target `protocol` must be `do53`, `doh`, or `synthetic_toy`. Every dataset supplies `path`, `label_column`, `label_mapping`, `feature_columns`, `provenance` and `split`; optional `id_column` and `group_column` preserve scientific grouping outside predictors. Labels map explicitly to integers 0/1; source and final evaluated partitions need both classes. `split` fractions are `train`, `validation`, `test`, `adaptation` summing to one. Source adaptation is zero. Within mode omits target. Zero-shot target adaptation is zero. Assisted target adaptation is positive, label blind and disjoint from test. Group fractions act on groups and can yield unequal row fractions.

Paths resolve relative to the working directory, so run commands from the project root. Saved synthetic `data/demo/*/demo-config.json` files are runnable examples using generated toy inputs and correct provenance. `research_plan.json` is proposed experimental metadata, not a runner input or completed result.

Model names are `lr`, `knn`, `svm`, `rf`, `xgb`, `mlp`; `model.params` supplies explicit estimator settings. All families use train-fitted median imputation; LR/KNN/SVM/MLP also standardize. SVM uses decision scores, not probability calibration. Global experiment `seed` controls splits, importance and random model parameters. `top_k` is one positive integer no larger than the eligible feature count. The demo `--all-k` sweep exercises 10/15/20 on one fixed synthetic dataset.
